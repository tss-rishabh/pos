# Native confirmation fixture scope

The confirmation runner installs the canonical authority-succession migration and uses the shared locked-owner native-head fixture, its two exact readonly metadata functions, separate source reader and projection publisher, authenticated synthetic complete publications, and a distinct application connection for the actual Go `Confirm` callback. The only new schema allowance is the existing disposable `pos_checkout_contract_test`; localhost/root installer guards remain. Root is used for fixture DDL, corruption vectors and observations, never as this Go financial caller.

Counter-selected mutation/concurrency fixtures enter real READ COMMITTED transactions under the application account, qualify the current full metadata and acquire the required customer/order/HP locks. Actual reviewed triggers update the projection. The raw literal COUNT oracle deliberately seeds anomalous rows before counter installation and proves only the original predicate. It does not certify those rows as accepted financial mutations. The expiry-wait case observes the actual stock wait and then crosses its bounded capability deadline; metadata-audit latency cannot make it expire before reaching that wait.

`run-go-tests.sh` retains default vet and `-race -mod=readonly`. The existing module cache is mounted readonly, and builds use a disposable task cache. The private file bridge has no service listener or provider port and never logs fixture credentials, SQL or parameters. Its Go-only cooperative entry is copied into the disposable assembly and is absent from production overlays.

The membership/cache runners copy the same canonical authority migration and use independent Go application accounts, retaining the literal EAV revision fences and their original financial behavior. Their Python source-stage/native descriptor and source callbacks remain separately bounded evidence. A local fixture-only source-repository/Python override makes pinned source reads usable in an isolated worktree without installing dependencies.
