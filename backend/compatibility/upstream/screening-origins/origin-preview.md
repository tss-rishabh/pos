# Genuine source cart preview integration

Implementation checkpoint; final source/native/browser validation is deferred
until all feature code is integrated. No selector is enabled by this change.

`origin_preview.validate` reexports the strict shared
`pos-screening-origin-preview-v1` validator. Preview IDs are generated by the
server after genuine customer JWT, legacy session/grant, MPos session/grant or
CSK service authentication. They are never Order commands or financial nonces.
Membership and coupon preview documents use their independent signed purposes;
neither document is accepted by the final real-command execution scope.

The installed Cart/ActiveCart middleware defers selected authenticated screening
carts before original MetaInitializer hydration. The original responder runs in
an owned READ COMMITTED transaction with current materialized counter replay,
read-only SQL, captured cart persists and deferred original source effects.
`NeedOriginMembershipHistory` and `NeedCouponPreview` unwind that transaction.
The private BQ readers run after all SQL connections are released; bounded replay
then reauthenticates current authority and compares the original request and
both current main/active cart namespaces. There is no historical native fallback.
Anonymous local carts retain the original guest path without a fabricated ID.

The literal pinned AddFreeMembership class is compiled independently. Its actual
process and >2000 short circuit are retained. Only its three historical SELECTs
and execution clock use authenticated complete member generations. An existing
active member does not execute those historical criteria. The final real Order
frame repeats selective qualification and validates the current mutation head.
Late callback/input changes cannot adopt a prior preview.

CSK uses its genuine source prefix. Original customer/address preparation is
frozen and encrypted before cart-history HTTP. The original strict CSK pricelist,
meta additions, product-add loop and forced-prepaid input execute in rollback
preview. Retries restore the frozen prefix rather than registering another
customer/address/cart. The native original attempt and active reference head
are rechecked on each pass. Same-authority explicit resume and pre-order
authority succession retain this exact prefix and its original customer.

Apply the reviewed additive `preview-migration.sql` through the deployment
registry before selecting these source consumers. It creates separate current
cart receipts, authenticated derived cart-tracking calls, and frozen CSK cart
prefixes. Successful cart persistence and encrypted original effects commit
together. The existing source effects CLI discovers the distinct cart journals;
its consumer verifies `scopeKind: cart-preview` explicitly. A missing/lost broker
outcome stays UNCERTAIN and is not blindly resent. Original source order effects
keep their existing absent-field signed bytes.

Bootstrap installs the existing member history URL/contract and derives the
coupon preview sibling from the qualified coupon-history URL. `source_hooks`
adds the origin middleware before the actual source app is constructed, and
mounts `coupon_control_application` after all original source routes. The real
stage-recovery resource is mounted through a static error boundary with closed
request/actor events; it cannot create a provider attempt.

Integration prerequisites are the committed shared preview/member contracts,
coupon preview helpers, actual current-counter publication/writer coverage,
and the separately authored genuine legacy cart staff-forwarding caller. The
original website repository observed empty remains an external client mount
acceptance requirement; this module does not claim a deployed website session.
