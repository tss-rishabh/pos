This independent proof binds the restored global expiry/day-close clients to native
authentication/check-in, real buildApp HTTP, current services and owned physical
MySQL fixtures. It does not certify a whole source base template or all fulfillment,
finance, checkout or notification features.

The pinned Django oracle executes `order/urls.py:107`, its complete expiry view and
tab-count helper on genuine QuerySets. Model id/Meta declarations and complete
ExpressLineItem come from pinned source AST. Unused Order/HasProduct fields are
omitted. ModelBackend/signature sessions and LoginRequiredMixin are real. Only the
source Redis check-in helper is bridged to the owned native check-in record, and
clock/host-calendar are fixed IST. No ORM or candidate principal/session doubles.

Both original base-layout expiry scripts execute in a VM with explicit browser,
jQuery/Swal, storage and IST-host clock bridges. They establish source grouped
30/5-minute warnings, persisted dedup/cleanup, 60000-ms default expiry interval and
foreground stale-day-close prompts with a full 10-minute snooze after dismissal in
base.html. The pinned no-sidebar layout has no day-close nag; its absence is asserted
explicitly, rather than claiming a second source nag implementation.
The UI bridge does not substitute any candidate HTTP response. It is not evidence
for all layout markup, source Redis integration or financial eligibility policies.

The candidate loads the actual built App on a non-fulfillment route with real signed
native sessions. The proof covers grouped 30→5 warnings, persistence/reload, another
visible tab, expired/inactive cleanup, a real day-close reminder blocking urgent
expiry, foreground-only day-close reads, full dismissal snooze, exact server-date
navigation, invalid/duplicate date queries and manual-refresh denial, stale check-in
scope and archived operator access. Native frontend DTO and source Django results
must match for the expiry rows/counts. A host-Los-Angeles browser and explicit
UTC/IST/invalid/ambiguous DST cases check the corrected business-zone interpretation.

Seams are deliberate: Node's Date-only test clock is fixed at
`2026-11-18T12:00:00Z`; timers, network and SQL are real. Browser Date-only advances
exercise spacing without waiting ten minutes. Visibility is controlled explicitly
for background-tab checks. Financial eligibility, target dates, stale status,
queries and amounts still come from actual services/native rows. The notification
WebSocket feature is not certified by this proof. Modal priority currently covers
the actual global financial day-close reminder, not checkout/payment submission.
No financial command route is invoked.

Python3.12, uv and an owned disposable MySQL8.0.39. The URL must use 127.0.0.1 with
an explicit port other than 54777 and database admission marker
`pos_rewrite_global_reminders`. The existing source-verified fixture builder creates

From backend:

```sh
GLOBAL_REMINDERS_MYSQL_URL="$OWN_PRIVATE_MYSQL_URL" \
  sh tools/global-reminders/run.sh /absolute/pinned/backend-pos-web
```

then runs the joined proof. Keep raw failure logs private (0600); browser errors may
include synthetic fixture DOM. Final output contains only source hashes, check names
and explicit boundaries. No release ledger/certification is advanced automatically.
