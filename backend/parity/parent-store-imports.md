## Source behavior retained

- Download preserves the three header cells, both source instruction texts, `1=>Active and 0=>Delete` and example `1234,1,1`. CSV serialization quotes cells consistently and failure exports neutralize spreadsheet formula prefixes.
- Parse Python-style integral decimal values, optional sign, leading zeroes, surrounding whitespace and embedded single digit separators. Preserve the normal parameter/error messages. Physical IDs stay exact strings/BigInts up to signed BIGINT maximum, never JS Number. Negative/out-of-range IDs, non-ASCII numeral spellings, invalid encodings, inconsistent fields and oversized files receive strict validation instead of unsafe/out-of-domain SQL. Files are bounded to256KiB/5000 records/128 characters per cell.
- Validate active store, then existing `parent_prod_id=0` product, then the requesting operator's store access. Messages remain `Not a valid store.`, `Not a parent product.`, `Not a valid store for requested user.`; zero IDs or non0/1 flags use `Required parameters are missing.` and malformed integers use `Error while traversing csv data.`.
- Configurable type3 parents select **all nondeleted children OR deleted children with positive nondeleted ProductStore stock in ANY store**. There is no hidden Size/type/is_avail/active-store predicate. A deleted child whose only positive association is itself archived is excluded. Simple type1 parents reset themselves; other parent types receive only the source parent association behavior, without an invented reset call.
- For existing reset targets, request stock0 with source comment `Product removed from store using bulk CSV upload.`. Parent association stock is not passed to the projection for configurable parents. Delete only selected family associations at the selected store. Active1 recreates that family with stock0/is_avail1/is_del0; active0 leaves them removed. Held-stock rows remain unchanged. Unselected archived children and other-store associations remain intact.
- Synchronize successful **parent IDs**, in CSV order, including a repeated parent used at different stores. No fabricated store0 or variant-expanded product-list payload. Fresh association row IDs are naturally allocated again; parity compares business associations/flags, not unstable auto-ID values.

## Deliberate atomicity, validation and access corrections

The source resets/deletes each row before one delayed final `bulk_create`. Repeated add/add pairs violate the verified physical unique `(product_id,store_id)` index **after deletion**; add/remove pairs still recreate the staged add. The real-source fixture reproduces both defects. Every repeated normalized parent/store pair is therefore marked failed before either destructive command executes. Other independent rows continue. This changes the broken duplicate-row behavior intentionally and is not described as a response-identical optimization.

The source inventory helper swallows routine failures, and task execution continues with deletion/reinsertion. New processing commits one row family—approved transaction-scoped reset, deletion/recreation, immutable before/after audit and queue progress—in one writer transaction/savepoint. Any projection/storage/audit failure rolls the entire row back and leaves it pending in a BLOCKED job. Earlier committed rows remain recorded and are synchronized on a later block/cancellation; resuming does not repeat them. The file is not falsely described as one all-or-nothing transaction. Families over1000 associations require explicit reconciliation; no silent truncation or partial family mutation.

The source view is LoginRequired for roles1–5 and both user types, unlike the separate internal-role1–3 stock importer. That access is retained with current writer identity/assignment checks. Global bypass belongs only to internal type1/role1; every franchise role, including role1, is restricted to assigned active FRANCHISE stores. Archived actors/stores or changed parent classification are rechecked while processing, rather than trusting preview or stale browser claims. Other operators cannot see/control another owner's jobs; current internal role1 can administer job ownership. No mandatory cashier check-in is invented for source global assignment administration.

It passes the configured atomic stock projection to both import services; this also fixes the previous worker constructor omitting the projection supplied to HTTP imports. It never arms an unverified legacy CALL for parent imports. No new daemon or transport is introduced.

IDs are deterministic per import/progress revision/chunk, and duplicate enqueue verifies the original bound payload. Subsequent completion after a partial block can re-synchronize earlier parents as absolute current catalog state under a new revision; it does not reapply their stock mutation. The approved replay-safe product-sync adapter retains the exact integer JSON body, idempotency key, timeout and no-redirect rules. Unknown delivery remains durable for retry; a delivered receipt is not dispatched again. Logs retain only fixed event/module/resource IDs and scalar actor/request/import/row/effect IDs, never original CSV/name/product descriptions, SQL rows or raw exceptions.

## Read routing and publication

Current reference preview/capabilities/recent progress use PRIMARY, while mutations, current identity/access, immutable job anchor and worker decisions use WRITER. Completed/cancelled jobs strictly older than24 elapsed hours route records/detail/failure downloads to BigQuery. The existing safe ceil-to-microsecond cutoff is retained. Unfinished work stays current operational state. There is no historical MySQL data fallback.

The separate configured views are `BQ_PARENT_STORE_IMPORTS_VIEW` and `BQ_PARENT_STORE_IMPORT_ROWS_VIEW`; blank/absent disables historical access. The concrete adapter binds `profile='parent-store'`, UUID, owner, checksum, exact created/updated snapshots, paging and terminal states; verifies complete distinct record coverage and counts before returning detail/rows/downloads; and rejects stock-profile, partial, stale or inconsistent publication.

Publication contract: `parent-store-import-history-contract.json` extends the existing stock contract with metadata `profile STRING='parent-store'` and record `job_profile STRING='parent-store'`. `cells_json` is the exact three-string tuple; `command_json` is null or strict `{kind:'parent-store',productId:STRING,storeId:STRING,active:BOOL}`. Publish immutable final job/row versions atomically, retaining all cancelled/failed rows, UTF-8 cell bytes, original UUID/actor/checksum/sequence and UTC DATETIME(3) semantics. Reader views must filter the same profile and join rows to the exact immutable job snapshot. Do not mix source `CsvUpload` IDs/failed_data into rewrite UUID receipts or fabricate execution results for old pending tasks. Existing legacy uploads/pending Celery tasks require reconciled cutover, not automatic re-execution.

Shared metadata-only BigQuery evidence has no rewrite import tables. Actual publication remains a deployment prerequisite; no external DDL/UDF/view/upload was attempted. The adapter and refusal behavior are executable, not a placeholder MySQL fallback. Current stock source projection remains the separately qualified `POS_STOCK_PROJECTION_CONTRACT` boundary; injected native fixture arithmetic is not deployed procedure certification.
