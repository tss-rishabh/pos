# Private membership history handoff

The Node order transport accepts server-prepared `CsvMembershipPrefetch`
evidence. Only its order capability adds `membershipHistoryHash`, authenticated
with the independent source-authority key and a distinct HMAC purpose. Ordinary
capabilities retain field absence and their previous signed bytes. Correction
and history hashes can coexist; confirmation/publication gain neither field.
The browser cannot supply this command field.

The private receiver validates the complete document, source capability binding,
operation/request/plan/customer scope, generation, history key, trusted time zone,
45-calendar-day window and both original expiry bounds before constructing a
SQL session. It copies that evidence and exposes a per-invocation ContextVar
reader. SourceRuntime no longer accepts an arbitrary startup history port that
could perform I/O while the order transaction is open.

The exact pinned AddFreeMembership implementation runs against the verified
in-memory SELECT adapter. Its eligibility clock uses the retained execution
second, even when preparation and source execution cross a second boundary.
Receipt expiry still uses the receiver's current clock and is never extended.
CSV `createdAt`, financial business dates and original prices are unchanged.
The original over-2000 and no-ordinary-items branches still run without history.
Missing history for a history-dependent branch is refused, not replaced with an
empty purchase history or an old-order MySQL query.

The private order HTTP body is bounded at 1,400,000 bytes to admit the existing
bounded history document plus plan/capability. Publication retains its previous
256,000-byte limit. No document, customer/contact data, key or body enters logs.

## Integration boundary

This is the actual transport/receiver/eligibility handoff. It does not yet select
the asynchronous preparation producer in the financial coordinator. Durable
preparation attempts, no-dispatch fences and explicit resume are a separate core
slice. Warehouse publication/freshness qualification and real private runtime,
provider and cooperating-writer acceptance remain required. No live contract is
enabled by this change, and no historical MySQL fallback is added.

## Verification

The membership bridge suite executes the actual Node transport and Python
receiver admission, then the complete pinned eligibility class with SQL/network
unavailable. It checks distinct concurrent customers, original time-window
retention, source short circuits, rejected/tampered/stale input before session
construction, and legitimate large/oversized private HTTP bodies. It is not a
complete importer-to-provider test.

```sh
POS_LEGACY_IMPORT_SOURCE_ROOT=/path/to/immutable-api-v2-2960-source \
  node node_modules/vitest/vitest.mjs run \
  tests/legacy-order-imports/membership-bridge.test.ts --maxWorkers=1
```

The source runner verifies regenerated byte manifests and existing protocol,
startup and tender vectors. Native financial/screening regressions use only
guarded disposable localhost schemas.
