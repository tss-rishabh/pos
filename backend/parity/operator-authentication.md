# Operator authentication and revocation

All operator authentication and permission/store scope reads use the writer. Session versions combine current credential fields with a monotonic per-operator epoch in `pos_rewrite_operator_auth_epochs`; cached role/credential states cannot reactivate an older token after a reversal. Successful MFA completion records `last_login` in the session creation transaction using configured business wall time. Password proof alone and ordinary session rotation do not change `last_login`.

`invalidateOperatorAuthentication` and its bounded500-operator batch variant run inside each sensitive mutation transaction while target operator rows are locked. Five set-based statements increment epochs, permanently revoke existing session rows, delete pending login proofs, clear OTP material while retaining lockout/cooldown budgets, and cancel pending authenticator enrollments for both target and initiating actor. The same epoch binds device QR grants. Profile password/contact changes rotate only the current browser to fresh credentials after committing revocation; changing MFA or affected group membership requires reauthentication. Explicit logout also discards that browser's pending MFA proof.

The browser sends its expected operator identifier; resource mutations require it and supplied mismatches on reads are rejected before handlers run. This assertion supplements cookie authentication and never grants access. Authentication and independently credentialed service routes retain their own protocols. The client captures actor IDs for asynchronous flows, aborts old-owner requests, checks identity after awaited binary consumption, and remounts the workspace on account changes. Observed revocation/session expiry clears identity, query/workspace state and catalog caches while retaining operator-owned carts, outbox and completed-sale evidence. Offline identity expires with its cached session; a disconnected client cannot learn an unobserved server revocation before reconnecting, and financial actions always require online authorization.

Readiness verifies applied checksums and unfinished DDL journal state without repairing schema. At cutover, every operator credential/status/permission/store-assignment writer must participate in epoch invalidation, or be disabled. Unpatched external/legacy writers cannot provide the restoration guarantee. No trigger or live database change was applied during this work.

Native tests prove password-proof-only denial, MFA replay prevention, permanent revocation after restoring settings, current-session password rotation, pending-proof logout, staff/superuser changes, actor and target enrollment cancellation, a501-member permission group across bounded batches, QR credential restoration, and current role/store authorization. Request/client tests cover stale-account actions, explicit captured actors, owner-change aborts and late binary results. Real Electron round trips and infrastructure review remain release prerequisites; these are bounded security checks rather than an unconditional production certification.
