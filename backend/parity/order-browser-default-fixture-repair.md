# Order browser default metadata fixture repair

Frozen r9 (`caba871`) retained two harness failures. The history browser fixture omitted default date metadata, so OrdersPage correctly displayed “The server did not provide the original order date window” and never mounted its list; the first View order501 wait expired after its original ten seconds. The payment fixture omitted the same metadata. Its expected invoice-publication error was present, but the unrelated missing-metadata alert made the original strict alert locator resolve two elements. This was not missing invoice failure feedback or a production date-policy defect. The archived failures remain unchanged.

Both intercepted options responses now carry the current `defaults` contract generated by production `sourceOrderDefaults`: generatedAt, timeZone and store placement bounds. This constructs realistic fixture metadata, rather than defining the expected result. The history expectation independently anchors the pinned source OrdersView semantics to fixed `2026-11-18T12:34:56Z`: Asia/Kolkata minute `18:04`, five days back to13Nov, and upper endpoint18Nov18:05. It compares exact placed/calendar bounds and operator1. It no longer assumes a today-only initial window. Browser Date and historical test dates use the same fixed epoch, retaining source row multiplicity, historical detail date scope and unknown-age link checks.

The payment fixture change adds metadata only. Its original invoice-error locator, confirmed-payment assertion, unrelated-cart preservation, other payment/cancellation checks and timeouts remain intact; the extra warning is resolved rather than hidden with a narrower locator. Source role-two/authorization and application behavior are unchanged.

Executed on separate current-code base `db8a4462054be5582e1fe48708274942488461e1`, whose defaults contract has `store` only (the earlier frozen graph also included `online`). The original history target passed all **5 checks** and the original payment target passed **17/17 tests**, with0 failures/skips. Both scoped TypeScript configurations, changed-harness ESLint and MJS syntax checks passed. [The receipt](evidence/order-history/browser-default-metadata.json) records exact input/output hashes and the unchanged frozen failure hashes.

These are actual React/client browser flows with controlled intercepted HTTP, not native database, real API or complete Django/source workflow certification. Only the two affected targets and scoped static checks ran; no broader verification run, production files or frozen r9 inputs were changed.
