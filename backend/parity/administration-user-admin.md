# Other-operator Django UserAdmin capabilities

Source `users/admin.py` customizes Django4.2.5 `UserAdmin` personal fields and inherits username, password, permission flags/groups/direct grants and important dates. `operator-admin.ts` replaces the other-operator scalar/photo/password workflow; `access-control.ts` handles source model grants and `mfa.ts` handles write-only authenticator provisioning. The source framework reference is [Django4.2.5 auth administration](https://github.com/django/django/blob/4.2.5/django/contrib/auth/admin.py).

Six explicitly traced APIs provide administrative-profile GET/PUT, password-reset POST, private image reservation/attachment POSTs and protected image GET. The read DTO includes username, first/last name, email/phone/OTP contact, age/gender, POS role, user type, OTP delivery, active/staff/superuser/MFA flags, password-configured boolean, last-login/joined wall strings and revision/capabilities. It never includes password hashes, MFA seeds, private object keys or signed read URLs. Submitted unknown fields, including raw image paths and MFA hashes, are rejected. Operator/salesperson and model-grant free-text searches use POST bodies; legacy GET lists reject search parameters so contact values stay out of access-log URLs.

Current active internal role1 staff authority and reconciled `users.view_posuser`/`users.change_posuser` model grants are checked on the writer. Mutations require the change grant. A non-superuser cannot modify a superuser; changing your own administrative identity requires another administrator. Password reset additionally requires an existing current staff superuser. These are explicit security restrictions beyond source delegation. Source model permissions never silently bypass POS role/store checks on other resources.

The profile editor covers username, all custom scalar fields, account status and editable important dates. Username validation/normalization matches16 native Django4.2.5 Unicode cases, including NFKC full-width/combined-letter normalization, non-BMP length and whitespace rules. Input limits bound transport work. Date strings retain the source's naive wall semantics (`USE_TZ=False`) and optional six microseconds; no `Date` or UTC conversion occurs. `BUSINESS_TIMEZONE` must match the actual deployed source zone during acceptance. Concurrent login/profile changes alter the whole-row HMAC revision and reject stale edits.

Profile/name/age/gender/date changes alone preserve authentication when credential material is unchanged. Username/contact/OTP method/role/type/active changes and password reset call root's shared `invalidateOperatorAuthentication` in the same writer transaction while holding the operator lock. This increments the persistent auth epoch, revokes sessions, removes pending login proofs, clears OTP material while retaining lockout budgets, and cancels pending MFA enrollments owned by the target or initiated by it. Restoring original field values cannot revive old authentication. Group/flags/store-assignment flows use the same revocation mechanism. Mutation receipts bind UUID/actor/resource/action/body HMAC and preserve safe results for dropped-response retries; password preflight authorizes before expensive hashing and rechecks authorization/revision under the final writer lock.

Password reset uses the root source-compatible password validators and Django-compatible PBKDF2-SHA256 with one million rounds. Password/confirmation remain write-only request-body values and mounted React input state. Existing hashed values are never loaded into those inputs or response projections. A successful reset clears input values, refreshes the safe profile and revokes existing authentication. The parent tracing and API error handler provide sanitized events; this module logs no submitted values or raw exceptions.

Managed profile/cover images reuse `image-lifecycle` and the existing `pos_rewrite_profile_uploads` / `pos_rewrite_profile_media_jobs` state. An opaque purpose-separated HMAC binds reservations to both initiating administrator and target operator, disjoint from numeric self-upload owners. Root injects `operatorImageStore` using the same private profile S3 store; no extra migration/worker is introduced. Existing private-bucket readiness, checksum/byte/decode limits, before-publication model-grant/revision checks and protected streaming apply. Cleanup retains every current reference across both profile fields, including inactive users, and records the actual initiating actor ID independently of the opaque reservation owner.
