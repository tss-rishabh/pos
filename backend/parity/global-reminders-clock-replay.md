# Native reminder/release-note browser clock replay

Frozen r9 (`caba871`) failed the first expiry-dialog assertion in `frontend/tests/global-reminders/native-app.ts:201` and the first New-badge assertion in `release-notes.ts:82`. These remain historical failures; the frozen checkout and original163-check report were not changed. Bounded initial-step diagnostics reproduced the missing shell/login transition against unchanged frozen production code, with the original five-second assertions.

The cause is a harness clock mismatch. The native fixture freezes Node Date at its synthetic epoch. Pinned Playwright `Clock.install` records an installation log timestamp using that Node `Date.now()`. After navigation its injected `_replayLogOnce` advances time by the browser's native wall clock minus that timestamp. The initial about:blank clock correctly matched the fixture, but the navigated document matched real wall time instead. The embedded native session was already expired relative to real time, so the application correctly cleared local identity and rendered Login. Its stores response decoded through the actual frontend schema with two rows and no issues; no empty-store/schema cause was established.

The suspected Chromium cookie-discard explanation was **refuted**: the cookie remained stored as a session cookie, and the authenticated current-session request included its cookie header. Native authentication returned200. No cookie contents, headers, request bodies or raw DOM were retained in the safe diagnostic snapshots.

The two harnesses now use Playwright `setFixedTime` before navigation and for their existing explicit Date advances. The pinned implementation retains fixed wall time while real timer ticks continue, including replay on new documents. This keeps the fixture time established before application code and preserves the later reload, navigation, visibility, snooze and authority-recovery controls. Session credentials, native authentication and all original assertions/deadlines are unchanged. No application/runtime code changed.

The corrected initial-step diagnostics passed both assertions against the frozen production graph: fixture time remained stable after navigation, the embedded session was future relative to page time, local pending-logout remained false, and the shell/context/trigger and expected expiry dialog were present. The credential still expired before the real clock, demonstrating that no expiry extension masked the problem.

They include cross-tab deduplication, reload, benign authority reads, modal priority, full-dismiss snooze, date/refusal behavior, assignment restoration and authentication archive denial, zone boundaries, role-specific note content/focus and absence of informational HTTP mutations.
