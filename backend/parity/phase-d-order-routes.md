Legacy `stores/forms.py:68` declares `slack_group_url = forms.TextInput()`. That is a widget instance, not a form field, so Django ignores it. #### Legacy HTTP helper (pos/order)

- **Base URL:** `MIGRATION_TO_API_V2` (L/POSAdmin/settings.py:666, int env, default 0) chooses `MAIN_API_V2_URL` (settings.py:449) or `API_V2_URL` (settings.py:448). The path is joined by plain string concatenation, `base + 'pos/order'` (L/order/views.py:2845-2848), so the base must end in `/`. The path is identical under both bases. Only cart reads differ (`'cart'` vs `'pos/cart'`, views.py:1658-1661).
- **Transport:** `requests.post(url, json=payload, headers=headers)` (2879). There is **no timeout** (requests default: wait indefinitely), no retries and no try/except. Redirects are followed (requests default).
- **Headers:** `Content-Type: application/json` and `Authorization: <raw JWT>`, with no `Bearer` prefix (2850-2853).
- **Token source:** the browser POSTs `auth_token` (2693 / 3168). The token was minted when the page loaded, in `CreateOrderView.get` (views.py:1517-1535):
  - With no customer connected to the tab, the subject is the storefront `MUser` with `user_type=8, pos_admin_id=request.user.id` (1518-1522).
  - When Redis `tab_id` → user_id exists, the subject is the connected customer (1528-1534).
  - On customer connect / cart sync it is reminted with `create_token(user_id)` (views.py:2010, 2060).
- **JWT algorithm:** `Helpers.create_token` (L/helpers/helpers.py:535-564):
  - Claims: `sub` = str(user_id); `iat` = naive `datetime.now()`; `exp` = now + `JWT_EXPIRY_DAY` days (settings.py:439). The `expiry_in_min` variant is not used for pos/order.
  - `iev: true` is added only when `email` is passed and the user is an exclusive member (539-555). **Every checkout caller passes only user_id, so `iev` is never present.**
  - Signing: `encodeJwt` HS256 with setting `SECRET_KEY` (helpers.py:527-528), or for `MUser.is_two_fa == 1` `encodeJwt512` HS512 with `SECRET_KEY_512` and a `"2f."` prefix (530-532, 559-561). If the `MUser` is missing, the literal token `"somethingwrong"` is returned (537).
  - Timezone: `USE_TZ=False`, `TIME_ZONE` comes from env (settings.py:257,263). PyJWT encodes the naive local datetime as if it were UTC. The offset of `iat`/`exp` therefore depends on the server TZ: UNKNOWN.
- **Response handling:**
  - `status_code != 200` → `logger.error("[AjaxOrderView] FAILED at self.order() | status_code=…")` (2754) and an HTTP 200 body `{"status":400,"message":"Something Went Wrong"}` (2755).
  - Fast checkout: `place_order` returns `{"status":400,"message":"Something Went Wrong"}` (3286-3287), and the view replies `{"status":400,"message":"Something went wrong"}` (3270).
  - On 200 the body is parsed with `resp.json()`; the keys `order`, `method`, `isValid`, `name` are read with no validation (2759-2763 / 3291-3295). A KeyError or empty body gives an unhandled 500 (the view returns None), and Django `handler500 = core.views.error_500` applies (L/POSAdmin/urls.py:22). Network exceptions are also unhandled 500s.
- **Logging:** failure logs carry the status_code only (2754, 2838). Success: `logger.info("[AjaxOrderView] SUCCESS | order_id=… transaction_id=…")` (2834) and the invoice info log (2806 / 3320).

#### Scope-2 gaps

- **P0. pos/order dispatch is hard-gated on non-legacy upstream contracts.** These are the projection, refund-allocation patch hash, customer consent and customer-context env checks (gateway.ts:331-338; service.ts:1860-1867). Per R/backend/parity/checkout.md:83-84,109 the upstream patches are not deployed, so against the pinned API-v2 no ordinary sale can be created (503). If the contract env is set but upstream does not echo `X-POS-Customer-*`, the order **is created upstream** and the rewrite then raises `CUSTOMER_CONTEXT_PROOF_MISSING` as uncertain (gateway.ts:234-244), leaving a created-but-unconfirmed order.
- **P0 (needs verification). JWT `iev: true` is emitted for exclusive members** (crypto.ts:27; repository.ts:64-79). Legacy checkout tokens never carry `iev`, because `create_token(user_id)` is called without email (views.py:1522, 1534; helpers.py:539-555). If API-v2 derives member pricing or eligibility from `iev`, cart, quote and order totals can differ from legacy. API-v2 handling of `iev`: UNKNOWN.
- **P1. 8-second timeout plus forced "uncertain" on every pos/order failure** (gateway.ts:215-223; service.ts:1959-1965). Legacy waits indefinitely and shows "Something Went Wrong" so the cashier can retry. In the rewrite, a slow but successful order becomes a manual reconciliation.
