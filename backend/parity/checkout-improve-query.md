## Physical gift-card issuance integrity

The verified `gift_vouchers.to_phone` is BIGINT NOT NULL while the literal POS constructor supplies an empty string. Native strict MySQL rejects it with1366. The v2 compatibility session uses the source column/ORM default0 only for that explicit absent-recipient value; it preserves the customer, voucher code, amount, validity and disabled state, and does not change SQL mode or schema. The native SQLAlchemy fixture proves construction and rollback; no frontend recipient phone is created. The legacy canceled-order availability shortcut is also rejected because its existing UNIQUE voucher_code survives cancellation; no row/value is deleted to enable reissue.

The new rewrite-owned0015 table indexes `(order_id,voucher_id)` and `(collection_id,voucher_id)` for bounded receipt verification. Legacy gift-card collection/unique-code locks use existing primary/unique indexes; no production legacy DDL was applied.
