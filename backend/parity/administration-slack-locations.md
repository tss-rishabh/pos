## Slack authorization

`slack-provider.ts` exports `readSlackOAuthOptions(env)` and `createSlackOAuthProvider(config,options,fetcher?)`. Root injects the optional provider as `registerAdministration(...,{slackOAuth})`. Default-disabled `SLACK_OAUTH_ENABLED` plus `DEMO_MODE` prevent accidental provider use. Enabling requires source `SLACK_CLIENT_ID`, `SLACK_CLIENT_SECRET`, exact same-origin HTTPS `SLACK_OAUTH_REDIRECT_URI=/api/v1/admin/slack/oauth/callback` and explicit comma-separated `SLACK_OAUTH_TEAM_IDS`. Only Slack's exact authorization/token endpoints are used; token exchange is a bounded10-second confidential POST with HTTP Basic client authentication, fixed redirect URI, no redirects and a32KiB streaming JSON bound. Unapproved workspaces/scopes/webhook origins and malformed/error responses fail with static messages. Unneeded provider access/refresh tokens are discarded. This follows Slack's documented [authorization flow](https://docs.slack.dev/authentication/installing-with-oauth/) and [code exchange](https://docs.slack.dev/reference/methods/oauth.v2.access/).

Slack supports optional PKCE, but enabling its public-client app setting is a one-way change and public-client exchange differs from confidential exchange. This implementation preserves the source confidential BFF model; it does not send or claim PKCE proof. No Slack app setting was changed. See [Slack PKCE requirements](https://docs.slack.dev/authentication/using-pkce/).

`POST /api/v1/admin/stores/:storeId/slack-connections` binds a UUID operation to its initiating operator, an HMAC of its already authenticated session cookie, current monotonic authentication version, whole-store revision and provider configuration version. State is a purpose-separated opaque HMAC; only its digest is persisted. Attempts expire after600seconds. All mutation phases use current writer role1/3, organization and active assigned-store checks. Source privilege checks are retained and franchise role1 requires an actual assignment. A fresh start supersedes earlier pending work; a fenced EXCHANGING claim prevents concurrent callback re-exchange. Publication rechecks every bound version after provider I/O. Cancellation, expiry, revoked authority, stale revisions and unknown outcomes cannot overwrite a store connection. A committed response can be replayed through its safe receipt.

The provider callback necessarily receives temporary OAuth `code/state` query parameters. They are never logged, persisted, echoed to UI or forwarded to another URL. Gateway/CDN/ingress callback query logging must remain disabled/redacted as in the root runbook; application logging already omits URLs/headers/bodies. Callback returns303 to `WEB_ORIGIN/?slackConnection=<UUID>` with no-store/no-referrer. Root initial navigation uses `frontend/src/pages/administration/slack-return.ts:pendingSlackConnection`; Administration consumes/removes that safe query after mounting and fetches an actor-scoped status/channel receipt. The store table opens Slack in the same window, supporting Electron's separate exact `POS_OAUTH_ORIGINS` allowlist without popups. Real Slack login may require additional exact trusted workspace/IdP origins; configured desktop round-trip remains an acceptance requirement.

Only the legacy store field holds the resulting webhook credential. Reads expose `slackConfigured`, never the URL. The source popup/BroadcastChannel secret handoff is replaced by direct protected publication; no webhook is sent to browser state. Manual blank edits preserve it, explicit removal clears it, and exact HTTPS incoming-webhook replacement is write-only. Manual Store PUT now applies the same current franchise assignment/category boundary as OAuth; a role1 franchise cannot use it to edit an unrelated in-house store or reclassify its own store. Slack explicitly identifies webhook URLs as secrets in its [incoming-webhook guidance](https://docs.slack.dev/messaging/sending-messages-using-incoming-webhooks/).

Apply `src/modules/administration/slack-migration.sql` through the root writer-only migration runner. The rewrite-owned table contains ephemeral state/lease/version IDs and safe completion metadata, no authorization code, webhook, token, cookie or contact values. Root security worker calls `pruneSlackConnections(db,now=Date.now())`: each run expires at most100 attempts and removes at most100 receipts older than24hours. Security proofs remain writer-authoritative; there is no historical authorization fallback.

## Location lookup

`location-schema.ts` contains read-only projections checked against `evidence/mysql-extra-schema.json`: `deliverable_pincodes.id` BIGINT, pincode VARCHAR32/nonunique index, Latin1 city VARCHAR20, INT zone/country references and string coordinates; zones.id is INT. It creates no legacy DDL. `POST /api/v1/locations/postal-code-lookups` accepts a bounded postal string in its body, requires an authenticated POS role and returns no-store. Active master-data lookup uses the primary reader, not report readers. The ORM query binds pincode equality, joins zone/country PKs and preserves source country/state labels and coordinate strings. It does not filter country/zone status because the source does not. Missing joins/unknown postal values return null, replacing the source empty object.

The physical pincode index is nonunique. Source `LIMIT1` has no explicit ordering; the rewrite explicitly selects lowest PK for a stable duplicate tie. An isolated native MySQL test executes the extracted source SQL with only the DB-driver `%s`→`?` placeholder adaptation, compares its chosen fixture row/DTO and exercises IDs above2^53. This demonstrates tested duplicate behavior, not a guarantee about every production source plan. Representative duplicate reconciliation remains required before full parity certification. Existing index `(pincode)` already carries the InnoDB PK and avoids adding a redundant `(pincode,id)` index.

`sourceCityTitle` preserves native Python cased-character boundaries, Latin1 case expansions, title-case exceptions and final sigma, with a small generated exception map recording Unicode version. The hash-verified source `get` method is executed across270 city vectors. The source AST is cached only within that isolated oracle process to avoid reparsing a large module for each case. Store create/edit reuse a field-action mechanism to fill city/state/country/coordinates while preserving address and city reference. Explicit lookup replaces the source debounced GET, keeps postal values out of access-log URLs, aborts on close and disables submission during lookup/offline work. Validation supports bounded international postal forms as the physical VARCHAR32 contract permits; the existing store field retains its source10-character capacity.
