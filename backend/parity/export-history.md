# Export metadata archive and authorization

`POST /api/v1/report-exports/search` accepts origin (`current` or `legacy`), activity (`recent` or `archive`), optional archive calendar dates, private search text, a finite sort/direction and pagination. The GET list remains a recent-history compatibility surface. Request filters and storage keys are never logged or exposed in URLs. The frontend uses bounded cancellable POST requests and polls only visible pending work.

Recent reads use the primary reader: all nonterminal operational jobs remain visible regardless of age, while completed/failed rows are included only within the preceding 24 elapsed hours. Archive reads use BigQuery for terminal metadata older than that cutoff. Calendar filters are interpreted in BUSINESS_TIMEZONE and intersect the cutoff, with a maximum 366-day range. There is no historical MySQL report fallback. Direct receipts, file eligibility and downloads use writer-current state because age does not transfer operational authorization to a warehouse.

`BQ_REPORT_EXPORTS_VIEW` and `BQ_LEGACY_REPORT_EXPORTS_VIEW` are explicit validated fully qualified compatible views. Both expose this metadata projection:

`id,kind,report_name,note,period_start,period_end,status,operator_id,requested_at,completed_at,format,byte_count,row_count,terminal_at`

The legacy view additionally requires `time_period STRING`, preserving the original source period label including NULL and empty. The current queue uses its original date range or current-snapshot/current-collection label. The source field is a nullable 55-character label, and the saved raw BigQuery schema confirms STRING; it is not a command/filter JSON payload. `raw-legacy-export.ts`, its generated SELECT proposal and the generated-literal validation fixture carry this exact field. Missing/malformed legacy period data fails closed. The prior raw-projection evidence predates this additional selected field; renewed cloud qualification is separate from local/source fixture validation.

Only `COMPLETED` and `FAILED` rows qualify. `terminal_at` is the completion/state timestamp used for elapsed-age and calendar filtering, not the requested timestamp of long-running work. New queue DATETIME columns are UTC; legacy DATETIME columns are business-local. Period strings preserve their original human meaning. UUIDs identify current jobs; legacy IDs are decimal strings. Counters/sizes are nonnegative integers and timestamps may be null. Legacy notes must be NULL because the legacy message field mixes user text with internal errors. The reader additionally suppresses any legacy note returned by a misconfigured view. No input JSON, storage key, object URL, raw error, customer field or credential belongs in these views.

Queries bind owner/date/search/limit/offset parameters and apply resource label `report-export-history`. Current writer role determines whether all owners may be listed; non-superadmins see their own requests. Actor display names are batched current metadata from the primary reader. Warehouse rows begin with `canDownload=false`; a writer batch checks actual file status and permissions before the API grants a download action. Missing mappings fail closed. Archived metadata cannot create, authorize or mutate an export.

New exports use immutable store/user-type snapshots and current role/assignment/account checks. Legacy files lack verifiable scope, so downloads require current internal user type 1 and role 1. This closes source global file disclosure and denies stale principals and restricted franchise superadmins. Approved-prefix, traversal, format, bucket-privacy and content checks still apply. A warehouse row without its authoritative queue row is metadata only.

Evidence includes bound warehouse routing/age/owner/search tests, missing-view and malformed-contract tests, and local MySQL checks of old pending work, archive eligibility, ownership, changed role/user type and legacy security corrections. `evidence/operational-reports/export-archive.json` and its screenshot record an isolated Chromium fixture with thirteen archive/cash-ledger UI/protocol checks and no real service calls. Live compatible-view reconciliation, SSO and production bucket checks remain deployment/acceptance requirements.
